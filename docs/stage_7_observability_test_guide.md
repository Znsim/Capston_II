# 7단계 오류 처리·관측성 테스트 가이드

## 적용 내용

- 프론트의 모든 예외 처리에서 사용자 메시지 또는 개발 로그를 남긴다.
- 사용자 화면에는 내부 예외·응답 본문 대신 간단한 안내와 요청 ID만 표시한다.
- 상세 오류 메타데이터는 개발 빌드의 브라우저 콘솔에만 출력한다.
- 프론트 개발 로그에는 요청 본문, 비밀번호, 쿠키를 출력하지 않는다.
- 모델 미로드, DB 오류, 질문 생성·조회, 추론, 답변 오류의 백엔드 로그 코드를 구분한다.
- 헬스 체크는 실제 DB `SELECT 1`과 모델·label encoder 적재 상태를 확인한다.

## 요청 ID 확인

1. 백엔드를 실행하고 프론트에서 의도적으로 잘못된 요청을 발생시킨다.
2. 사용자 오류 메시지에 `요청 ID: ...`가 표시되는지 확인한다.
3. 같은 ID가 응답의 `X-Request-ID`와 서버 로그에 존재하는지 확인한다.
4. 브라우저 개발 모드 콘솔에는 상태 코드, 오류 코드, 요청 ID가 표시되는지 확인한다.
5. 운영 빌드 콘솔에는 상세 오류가 출력되지 않는지 확인한다.

## 장애별 확인

### 모델 미로드

1. 테스트 환경에서 모델 경로를 존재하지 않는 파일로 설정하고 서버를 시작한다.
2. `/api/health`가 `503`, `ai_model: not_loaded`를 반환하는지 확인한다.
3. 키오스크에는 모델 준비 실패 안내와 요청 ID가 표시되는지 확인한다.

### DB 장애

1. 테스트 DB 연결을 중단한다.
2. `/api/health`가 `503`, `database: error`를 반환하는지 확인한다.
3. 질문 저장 또는 역무원 목록 조회 시 사용자용 DB 연결 안내가 표시되는지 확인한다.
4. 로그에 질문·답변 본문이나 DB 비밀번호가 없는지 확인한다.

### 카메라 장애

1. 웹캠 권한을 거부하거나 다른 앱에서 웹캠을 점유한다.
2. 권한 거부·카메라 없음·사용 중 상황에 맞는 안내가 표시되는지 확인한다.

## 정상 헬스 체크

```powershell
Invoke-RestMethod http://127.0.0.1:8000/api/health
```

정상 예상값:

```text
database          : connected
ai_model          : loaded
all_systems_ready : True
```

## 완료 체크

- [ ] 프론트에 빈 catch 블록 없음
- [ ] 사용자 메시지와 개발 로그가 분리됨
- [ ] API 오류 메시지에 요청 ID가 표시됨
- [ ] 모델·DB·카메라 장애가 각각 안내됨
- [ ] 대화·추론·답변 로그 코드가 구분됨
- [ ] 헬스 체크가 실제 DB와 모델 상태를 반영함
