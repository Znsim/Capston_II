# 제안서 대비 최종 프로젝트 변경 사항

## 1. 비교 기준

- 제안서: `[양식]_캡스톤디자인2_제안서 (1).pdf`
- 보조 PDF: `캡디II_제안서.pdf` (텍스트 레이어가 없는 스캔본)
- 최종 구현 근거: 실제 코드, `README.md`, 모델 카드, 모델 평가 보고서, 새 컴퓨터 검증 보고서
- 현재 최종 구현의 핵심: **정적 한국 수어 지문자를 한 글자씩 인식해 문장을 조합하고, 해당 질문을 역무원 화면으로 전달해 답변을 받는 키오스크**

## 2. 한 문장 요약

제안 단계에서는 연속 수어를 BiLSTM으로 인식하고 LLM과 교통 API로 자동 답변하는 범용 시스템을 계획했지만, 최종 단계에서는 학기 내에 실제로 안정적으로 동작하고 검증 가능한 범위를 우선하여 **MediaPipe Hands와 MLP 기반 32클래스 지문자 인식, 문장 조합, 역무원 중계, 음성 입출력, 장치 관리, 보안·배포 기능을 갖춘 실행 가능한 키오스크 시스템**으로 구체화했다.

## 4. 제안서와 동일하게 달성한 내용

- 웹캠과 MediaPipe를 이용한 실시간 손 좌표 추출
- AI 인식 결과를 텍스트 문장으로 구성하는 키오스크
- React 사용자 화면과 별도 `/admin` 역무원 화면
- FastAPI 기반 REST·JSON 통신
- 역무원이 사용자 질문을 확인하고 답변하는 양방향 소통 흐름
- 큰 버튼과 단순한 화면 구조를 적용한 접근성 중심 UI
- 웹캠·마이크·스피커를 활용하는 프로토타입
- GitHub 코드 관리 및 실행·테스트·배포 문서화

## 5. 제안서보다 추가·강화된 내용

- `none`을 포함한 32클래스와 운영 신뢰도 임계값 0.80 명문화
- Python과 웹의 좌표계 차이를 맞추는 `x -> 1-x` 변환
- 모델·라벨 인코더 SHA-256 및 63차원·32클래스 무결성 검증
- 질문별 `conversation_id`와 장치별 답변 분리
- 관리자 세션 인증과 보호된 장치 등록·수정·선택 기능
- 중복 전송, 빈 답변, 잘못된 로그인, 백엔드 중지 등 오류 처리
- 요청 ID, 속도 제한, CORS, 운영 환경 비밀값 검증
- SQLite 마이그레이션·백업과 모델 자동 배치 스크립트
- React 29개와 Python 9개, 총 38개 자동 테스트
- Python·Node.js 없이 실행 가능한 Windows 포터블 EXE

## 6. 수행하지 않았거나 후속 과제로 남은 내용

다음 항목은 최종 구현 기능으로 말하면 안 된다.

- 연속 동작 일반 수어 또는 단어 수어 번역
- BiLSTM/Transformer 운영 모델
- 얼굴 표정·상체 동작을 모델 입력으로 사용하는 번역
- LLM 기반 문장 교정과 자동 답변
- 공공데이터 교통 Open API 연동
- Google STT·Whisper의 WER 비교, WebRTC VAD, 잡음·반향 제거
- 실제 지하철 안내방송의 실시간 텍스트 변환
- TensorFlow Lite 변환
- dim/near/far 조건별 최종 라이브 정량 평가
- 학습에 참여하지 않은 독립 평가자 검증
- 청각장애인 3~5명 대상 SUS 및 과업 완수율 평가
- 실제 역사 배치, 공인 도메인·HTTPS, Windows 코드 서명

## 7. 발표에서 사용할 설명 예시

### 30초 설명

“제안 단계에서는 연속 수어를 BiLSTM으로 인식하고 LLM과 교통 API를 연결하는 폭넓은 구조를 계획했습니다. 개발 과정에서 연속 수어는 대규모 시계열 데이터와 독립 사용자 검증이 필요해 한 학기 프로젝트에서 신뢰성을 확보하기 어렵다고 판단했습니다. 그래서 최종 범위를 정적 한국 수어 지문자 32클래스로 명확히 하고, MediaPipe Hands의 63차원 좌표와 MLP 모델로 문자를 인식해 문장을 만드는 방식으로 변경했습니다. 대신 역무원 양방향 응답, 관리자 인증, 장치 관리, DB 마이그레이션, 오류 처리, 자동 테스트 38개와 포터블 EXE까지 구현해 실제 실행 가능한 완성도를 높였습니다.”

### 모델 변경 질문에 대한 답변

“BiLSTM은 여러 프레임의 연속 동작을 학습할 때 적합하지만, 최종 운영 대상은 한 프레임에서 구분 가능한 정적 지문자입니다. 따라서 21개 손 랜드마크의 63차원 좌표를 입력하는 MLP가 문제 정의와 데이터 형태에 더 적합했고, 구조가 단순해 실시간 추론과 배포도 안정적이었습니다. BiLSTM 실험 코드는 삭제하지 않고 연구 폴더로 분리했습니다.”

### LLM과 교통 API를 제외한 이유

“LLM 자동 교정은 사용자의 질문 의도를 바꾸거나 환각을 만들 수 있고, 교통 API는 노선별 데이터와 실시간 정확성을 별도로 검증해야 합니다. 이번 최종본에서는 사용자가 조합한 문장을 그대로 역무원에게 보내 사람이 확인해 답하도록 하여 정보의 책임성과 전달 정확성을 우선했습니다. 자동 교통 안내는 현재 시스템 위에 추가할 수 있는 후속 기능입니다.”

### STT 계획이 달라진 이유

“Google STT와 Whisper를 별도로 비교하고 역사 소음 제거까지 구현하는 계획은 축소했습니다. 대신 역무원 화면에서 브라우저 음성 인식으로 답변을 입력하고, 키오스크에서는 답변을 화면과 TTS로 제공하는 핵심 소통 흐름을 완성했습니다. 따라서 음성 편의 기능은 구현했지만 전문적인 역사 안내방송 STT 시스템이라고 표현하지는 않습니다.”

### 정확도 질문에 대한 답변

“normal 조건 660개 평가에서 전체 정확도는 96.67%, 신뢰도 0.80 이상으로 실제 인식된 결과의 정확도는 98.14%, `none` 정확도는 100%였습니다. 다만 평가자가 학습 데이터 수집에 참여했기 때문에 독립 평가 결과는 아니며, dim·near·far와 외부 사용자 평가는 후속 검증으로 남겼습니다.”

### 질문을 연속 전송할 수 없는 이유

“현재 키오스크는 한 질문의 답변이 완료된 뒤 다음 질문을 전송하도록 설계했습니다. 기능 부족이라기보다 질문과 답변이 섞이거나 중복 저장되는 것을 막기 위한 순차 대화 정책입니다. 서버 계층에서는 `conversation_id`로 여러 장치와 여러 질문을 분리할 수 있습니다.”

## 8. 발표 표현 시 주의사항

- “수어 번역기”보다 **“한국 수어 지문자 기반 교통 의사소통 키오스크”**라고 표현한다.
- “일반 수어를 인식한다”가 아니라 **“정적 지문자 31개와 중립 자세를 분류한다”**고 설명한다.
- 96.67%를 전체 사용자·전체 환경 성능으로 일반화하지 않는다.
- 조건별 실사 평가를 데이터 증강으로 완전히 대체했다고 말하지 않는다.
- “AI가 교통 정보를 자동 답변한다”고 말하지 않는다. 현재 답변 주체는 역무원이다.
- 미완료 항목은 실패가 아니라 범위 관리와 후속 확장 계획으로 설명하되, 수행 여부는 정확하게 밝힌다.

## 9. 결론

최종 결과물은 제안서의 모든 AI 모듈을 그대로 구현한 시스템은 아니다. 대신 가장 중요한 문제인 **청각장애 사용자가 손으로 문장을 작성하고 역무원과 실제로 질문·답변을 주고받는 흐름**을 끝까지 동작하도록 완성했다. 연구 범위는 연속 수어 자동 번역에서 정적 지문자 입력으로 축소됐지만, 서비스 범위는 인증·장치 관리·오류 처리·DB·테스트·배포까지 확장됐다. 발표에서는 이를 “기능 축소”만으로 설명하기보다 **모델 범위를 현실적으로 재정의하고 시스템 완성도와 신뢰성을 높인 설계 변경**으로 설명하는 것이 적절하다.
